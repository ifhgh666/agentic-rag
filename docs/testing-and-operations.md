# 测试、配置、数据、安全与本地运行操作

适用：工程验证、依赖安装、启动/重启、日志、索引和数据操作。命令是候选操作入口，**不是每次任务都要执行的清单**。先确认已有环境、批准范围、实际进程和可用脚本。

## 1. 配置与保密要求

- 必须保留已有 `backend/.env`；仅在它不存在时允许依据 `.env.example` 初始化。密码只存哈希，密钥由配置提供；不得写入代码、报告、命令行或版本控制。
- 普通日志和公共 SSE 不得暴露密钥、完整提示词、私有推理或异常内的敏感信息。详细本地诊断只能在批准范围内使用，不随意新增扩大原始输入访问范围的接口。
- 读取实际配置只输出非敏感值；不要把 README 中的旧预算作为 005 的当前运行依据。

## 2. 测试数据、知识库和迁移

- 单元/集成测试使用临时数据目录及独立 Qdrant 目录；避免触碰正式 PDF、索引、运行中锁和用户会话数据。
- 不能为了测试而重建正式知识库。正式索引迁移按 README 的现行要求先预览、备份，并在应用迁移前停止后端；迁移完成后验证索引清单及 `index_ready`。
- 离线工程检查与真实模型冒烟、失败题复验、正式题集评测分别对待。未授权不得把测试扩展为下一批正式评测。
- 回归测试覆盖变更行为和具体失败路径；优先复用 `backend/tests/conftest.py` 里的临时数据、fake provider 和隔离索引。不要新增仅重述实现细节的脆弱测试。

## 3. 开发与测试命令

从仓库根目录执行 `python start.py` 可一起启动后端和工作台。首次缺少 `backend/.env` 时会从示例创建，填好模型接口配置后重新运行。该入口只监听 `127.0.0.1`，使用本地演示账号 `admin / 123456`，自动准备密码哈希和进程内 JWT 密钥。重启后需重新登录。已单独启动前后端时，先停止对应进程以释放 8000 和 5173。

`.env.example` 面向上述本地启动入口，只列出当前生效的常用配置。研究分支的工具、迭代和压缩边界由 `backend/app/rag/graph_state.py` 定义。手动直接运行 Uvicorn 时，需另行通过环境变量设置 `ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH` 和 `JWT_SECRET`。

以下命令已按 2026-10-09 的目录与前端 scripts 核对；执行前仍须确认本机脚本、工作目录和环境。`python` 指向当前已配置 Python；历史上用过 `D:/newsoft/python.exe`，但**不能假定仍然存在或可用**。

| 操作 | 工作目录 | 命令 / 何时执行 |
|---|---|---|
| 后端依赖 | `backend` | `python -m pip install -r requirements.txt`；仅缺依赖或获准改依赖时 |
| 启动后端 | `backend` | `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000` |
| 前端依赖 | `frontend` | `npm install`；仅首次安装或确需同步时；留意当前锁文件及项目包管理器 |
| 启动前端 | `frontend` | `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort` |
| 后端工程检查 | `backend` | `python -m pytest -q tests/unit tests/contract tests/integration tests/security` |
| 前端单测 | `frontend` | `npm test -- --run` |
| 前端类型与构建 | `frontend` | `npm run build`；当前脚本包含 `tsc -b`、`vite build` |
| 健康检查（PowerShell） | 根目录或任意目录 | `Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/health'`；核对 `index_ready` |

本轮核对的 package.json 没有 `npm run lint`，不得编造执行结果；以 `frontend/package.json` 实际 scripts 为准。

## 4. 如何选择验证

1. 后端行为变化：优先相关单元/契约/集成测试；阶段交付根据已批准计划完成必要的后端工程检查。
2. API、工具事件或 SSE 变化：检查后端 schema/序列化、前端类型和消费端，并运行关联契约测试。
3. 前端变化：运行相关单测和构建。依赖变化先确认已有锁文件、工具链与网络需求。
4. 纯 Markdown 维护：检查 UTF-8、结构、链接目标和命令来源；无需启动模型、全量测试或重建索引。
5. 报告列出工作目录、实际命令、退出码、结果及原始记录；没有执行的检查不能称为“通过”。未触及模块无需无理由重跑其全部检查。

## 5. Windows 进程、服务与交付

- 启动/重启前核对实际端口与进程归属；停止服务不要按进程名批量结束无关进程。
- Windows 后台服务应使用隐藏窗口并保存启动日志；若重启会清空进程内缓存、会话或待澄清状态，在报告中说明实际影响。
- 中文文档用 UTF-8 写入后重新读取确认，交付时提供确实存在的可点击文件路径；仓库内部文件相互引用采用相对路径。
- 原始运行记录、历史失败、模型输出和评测记录不覆盖；诊断产物要区分正式/模拟与初次/补测。
