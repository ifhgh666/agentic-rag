# RAG 模型循环、答案依据与评测规范

适用：005 模型驱动循环、回答核验、真实模型测试、正式题集评测。实施前还须读取当前功能的 `spec.md`、`plan.md`、`tasks.md` 和最新报告。本文件对评测行为作原则约束，**不代替批准的题集协议、模型配置与最终评分标准**。

## 1. 005 模型与程序职责

- 已批准的 `005-model-driven-agent-loop` 要求模型决定检索查询、是否继续、是否读取 Parent 及如何回答；程序执行工具、合法性检查、引用定位、隔离、缓存、预算和超时控制。
- 不能在不经新规格批准的情况下恢复旧式语义规则决策，也不能将程序的安全/预算校验当成模型的语义决策。
- 答案中的文档事实必须有检索原文依据，引用须能逐字定位；资料不足应说明不足，不得编造设备阈值、关键操作步骤或不存在的引用。
- 用户题设数值可以用于模型比较与推导；应清晰区分**题设条件、文档原值和推导结果**，不能私自改写用户数字，不能用原文强制覆盖模型结论，也不能用引用定位成功掩盖数值推导错误。

## 2. 不同验证各自能证明什么

| 验证类型 | 能证明 | 不能证明 |
|---|---|---|
| 单元/契约/集成/安全测试 | 工程行为和具体断言 | 自动证明真实问答质量 |
| fake LLM、deterministic embedding | 流程、控制分支、接口隔离和稳定复现 | 真实语义检索、真实模型工具决策和正确答题 |
| 引文逐字定位 | 引用文本存在、定位正确 | 结论推理、数值和步骤完整性正确 |
| 离线 RAGAS | 按所选指标提供诊断信号 | 自动替代人工验收或全部业务正确性 |
| 真实模型与人工逐题验收 | 当前冻结条件下的真实表现 | 推广到未测试环境和全部问题 |

对未测维度明确标记“未评估”，不输出没有依据的总体质量分数。

## 3. 正式题库与对比评测协议

1. 按已批准计划规定的**题目顺序、会话分组和首次回答**协议执行；不将标准答案注入被测平台，不自动追问、重试后选最好成绩或改写失败记录。变体、补测和首次测试分开记录。
2. 保存：原问题、标准答案、平台原始回答、逐题评分依据、最终计分规则、端到端耗时、失败与 timeout、题目是否实际运行。
3. 冻结并标注题库版本、知识库/索引版本、真实模型身份、可披露的配置快照、评分规则；不得把旧版本成绩冒充新版本结果。
4. 引文核验、数值正确性、推导与步骤完整性分别评分；未运行题目不得自动按“通过”或伪造得分。
5. 保存真实记录的可追溯位置。模型/工具调用次数、请求 ID、各边界事件耗时及 token/用量来源如实描述；无法取得的字段写“不可得”，不能估算冒充实测。

## 4. 预算、时延与 SSE

- 对整个请求设**单一持续计时的总截止时间**；后续节点、重试或进度事件不得重置。当前 005 已批准总上限为 **300 秒**；执行前还应核对当前规格、生效配置和 [`CURRENT_STATUS.md`](CURRENT_STATUS.md)，未经用户调整不得提高。
- 单次模型/工具等待同时服从节点上限、调用预算和请求剩余时间。总期限触及后直接记录 `timeout`，保存现场和原始结果。
- SSE 记录必须区分节点执行时实时产生的事件与运行完成后回放的事件；不能把完成后回放说成逐节点实时推送。
- 正式评测失败时保存失败证据并遵守批准的停止条件；恢复或补测属于下一次明确授权，不默认跳到下一题或下一阶段。
