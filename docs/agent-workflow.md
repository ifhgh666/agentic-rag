# 编码代理开发流程与阶段交接规范

适用：规格、计划、任务拆解、实现、阶段验收、交接。本文件由根目录 [`AGENTS.md`](../AGENTS.md) 按任务指向；**不是 Codex 自动发现的根指令文件**。

## 1. 任务启动检查

1. 完整读取根 `AGENTS.md` 和 `README.md`；功能变更另读 `.specify/memory/constitution.md`。
2. 依据用户请求、`.specify/feature.json` 与具体文件核对当前功能；阅读相应的 `spec.md`、`plan.md`、`tasks.md`、最新阶段报告和相关失败清单。不得仅凭分支或修改时间判定阶段，也不能把导航指针当成授权。
3. 运行 `git status --short`、`git diff`；另看未跟踪文件。保留所有既有工作，不做无关清理。
4. 在动手前用简短文字指出本轮范围、当前阶段、预定验证和停止点。只有存在真正阻断性矛盾时才请求澄清。

## 2. 项目内 Spec Kit 技能选择

制定或修改实施计划时，应读取并实际遵循项目 `.agents/skills/` 下**对应的 `SKILL.md`**，将文档保存到仓库，而不是只在聊天里写计划。

| 目的 | 技能文件（路径相对仓库根目录） |
|---|---|
| 新功能需求规格 | [speckit-specify](../.agents/skills/speckit-specify/SKILL.md) |
| 必要需求澄清 | [speckit-clarify](../.agents/skills/speckit-clarify/SKILL.md) |
| 技术方案、分阶段计划 | [speckit-plan](../.agents/skills/speckit-plan/SKILL.md) |
| 任务拆解和依赖 | [speckit-tasks](../.agents/skills/speckit-tasks/SKILL.md) |
| 规格/计划/任务一致性 | [speckit-analyze](../.agents/skills/speckit-analyze/SKILL.md) |
| 按批准范围实施 | [speckit-implement](../.agents/skills/speckit-implement/SKILL.md) |
| 对照现有实现补齐遗漏任务 | [speckit-converge](../.agents/skills/speckit-converge/SKILL.md) |

- 根据当前工作选择技能，不能因为一次解释或小型文档修订就凭空创建 feature。
- 计划写明各阶段的目标、范围、验收方式、报告路径、停止点，并明确计划阶段与 `tasks.md` 中 Phase 的对应关系。
- 复用已有计划先核对、必要时更新；不得覆盖已完成任务、历史阶段报告或失败记录。
- 用户仅授权“制订计划”时，提交规格/计划/任务等文档供检查，**不执行实施**。
- 技能要求默认“执行全部任务”时仍服从本项目的单阶段限制和用户当前授权。
- 技能不存在、受阻或需用户决定时，列出缺失项、实际阅读过的技能路径、相关要求与影响；不得假称已执行。

## 3. 单阶段执行协议

1. 用户点名“执行阶段 C”仅执行 C；对整体计划说“执行”，默认只做第一个未完成阶段。
2. 阶段内完成必要的实现、修复、隔离测试及相关文档更新，及时更新 `tasks.md` 的工程任务状态，不必每个微步骤反复询问。
3. 若验证失败，保存原始证据和失败记录，按已批准的失败停止条件结束相应测试；不得挑选重试中的最佳成绩作为第一次测试结果。
4. 完成或中止当前阶段后，先保存报告到 `specs/<功能目录>/phase-<阶段>-report.md`（或沿用既有约定命名），再在聊天中交付链接、结论与待验收项。
5. **报告交付即本轮停止**；用户沉默、时间经过、状态询问、新的无关任务都不构成继续授权。不得后台自动启动后续阶段或评测批次。
6. 用户要求暂停、先写报告或切换任务，停止扩展旧任务范围；新任务结束后不能自动恢复旧计划。
7. 后续用户明确授权诊断、修复或补测时分别记录；只有明确验收并指示继续，才进入下一阶段。

## 4. 阶段报告必备内容

- 阶段目标、授权范围、实际改动、主要文件、尚未实施部分。
- 实际执行命令、工作目录、退出状态、测试记录与原始证据链接；“未运行”“环境阻塞”“失败”与“通过”明确区分。
- 真实模型/检索与 fake/mock/deterministic 测试分别给结论；工程检查与回答质量验收分开表述。
- 问答/评测相关：模型和工具调用、请求 ID、实际耗时、用量来源、失败与限制；不得编造分数或时延。
- `tasks.md` 状态、阶段结论（通过/未通过/待验收）、当前失败清单差异、下一阶段范围。
- 明示：**“报告后暂停，等待用户验收”**。

## 5. 文件和状态职责

- `spec.md`：功能需求和验收标准；`plan.md`：设计与分阶段实施；`tasks.md`：任务和工程完成状态。
- 阶段报告：不可覆盖的历史事实；`CURRENT_FAILURES.md`：当前失败清单（以仓库现有约定为准）。
- `docs/CURRENT_STATUS.md`：仅供快速交接的日期化快照，不覆盖最新报告/实际运行配置。
- 若 README、报告、规格和现有实现产生冲突，先核对用户最新要求与当前批准的规格，再核对真实代码和配置，说明仍未消除的差异。
