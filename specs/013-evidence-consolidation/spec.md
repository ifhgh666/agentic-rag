# Feature Specification: 第一组证据能力合并

**Created**: 2026-10-22
**Status**: 单阶段 A 工程完成、待用户验收，见 [阶段报告](phase-a-report.md)。
**Input**: 用户选择第一组、接受移除旧入口，随后要求“继续，这次不用这么麻烦，直接执行计划”。本轮包含必要规划、第一组合并、隔离验证和报告。

## User Scenarios & Testing

### User Story 1 - 在同一处理解证据处理 (Priority: P1)

维护者希望完整原文恢复与证据处理放在一起，减少查阅跳转，同时保留已有独立能力和问答表现。

**Why this priority**: 唯一已选择的候选，范围小、归属明确。
**Independent Test**: 合成材料对照前后原文恢复、安全读取、证据选择与来源输出，确认主流程不重新启用旧策略。

**Acceptance Scenarios**:

1. **Given** 匹配或过期的派生原文，**When** 恢复段落，**Then** 前后得到相同完整单元或空结果，不拼接原文外步骤。
2. **Given** 合法、缺失、过大、不可解码或其他文档目录的材料，**When** 读取，**Then** 原安全允许/拒绝行为保持，不重新解析原始文档。
3. **Given** 完整或不完整单元，**When** 筛选证据，**Then** 仍只允许同时存在于保留正文和提示内容的完整原文。
4. **Given** 独立调用和正常问答，**When** 合并并迁移仓库内调用者，**Then** 独立能力保持，正常问答不新增旧策略或模型调用。

### Edge Cases

- 不因没有当前调用而删除辅助能力。
- 旧入口移除已被接受；仓库外调用者需迁移。
- 表格、标题、列表、断行、空文本和不完整段落处理保持。
- 目录校验、大小上限和读取失败处理不可放宽。

## Requirements

### Functional Requirements

- **FR-001**: 合并选定的原文恢复与证据处理，保留所有函数、参数、结果与错误处理；唯一兼容变化为旧入口移除。
- **FR-002**: 迁移仓库内全部直接调用，不保留转发文件。
- **FR-003**: 保持独立证据选择和来源转换；正常问答不恢复旧策略。
- **FR-004**: 仅处理第一组；不调整提示、工具、预算、聊天协议、前端、编码或索引职责。
- **FR-005**: 使用既有测试和必要边界检查，以合成/临时数据及受控提供商验证；禁止真实模型、网络和正式数据访问。
- **FR-006**: 保留历史失败及既有修改，记录命令、结果、结构和未测范围，报告后停止。

### Key Entities

- **完整原文单元**：带完整性与顺序的文本。
- **证据记录**：带正文、提示内容与来源定位的既有记录，形状不变。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 选定范围内源文件减少一份，无替代转发文件。
- **SC-002**: 搬移能力全部保持，仓库内旧入口直接引用为零。
- **SC-003**: 相关隔离检查无新增失败，原失败不通过删除断言消除。
- **SC-004**: 真实模型、网络和正式数据操作为零；报告明确未测质量及运行限制。

## Assumptions

- 用户已接受旧入口失效，不承诺仓库外调用自动兼容。
- 仅代码组织整理，无性能或真实质量提升承诺。
- 不重启现有服务，不开展另外两组合并。
