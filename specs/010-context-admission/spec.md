## Problem Statement

用户希望动态 Token 阈值真正限制证据装载，并在工具结果过大时让模型获得可操作的容量反馈，而不是先把整个结果加入消息，随后直接因输入超限结束。

当前模型循环计算并传递动态阈值，但实际停止条件使用完整输入的物理上限。证据大小、工具载荷、消息结构和引用登记分散处理，容易产生“配置存在却不控制装载”的理解差异。既有三次真实云端验证均因上下文容量结束；这些历史结果说明容量问题具有实际影响，但不能证明上述差异是全部失败的唯一原因。

仅让动态阈值生效也不能保证所有问题都能回答。单条 Child 可能超过可用容量，模型也可能未能在现有调用和时间预算内选择可装载的范围。系统必须诚实呈现这些限制。

## Solution

将上下文计量、容量判定和已读证据登记集中到一个有明确职责的 module。动态阈值约束当前模型输入中的证据文本，物理上限约束完整输入，两者同时成立才允许送入模型。

新工具结果必须在加入模型消息和登记引用之前进行容量检查。无法完整装入时，不装入该结果中的证据，也不将它登记为模型已读；改为返回与工具调用对应的简短容量反馈。模型可以选择更少的结果、更小的原文窗口，或依据已经装入的证据回答。

保留已经装入的证据，不自动摘要、裁剪、替换或语义筛选。不足以继续时明确记录容量、调用额度或时间原因；不把容量受阻冒充为知识库没有资料，不增加任何既有预算。

## User Stories

1. 作为配置使用者，我希望动态阈值真正约束证据装载，以便配置含义与运行行为一致。
2. 作为配置使用者，我希望证据预算与完整输入上限分别生效，以便提示词和工具定义不会被遗漏计量。
3. 作为提问用户，我希望系统按当前调用实际输入的证据文本计算容量，以便不会因证据登记去重而低估占用。
4. 作为提问用户，我希望同一份证据在当前消息中出现两次时计算两份占用，以便重复工具返回不会绕过容量限制。
5. 作为提问用户，我希望下一次调用重新计算当前输入，而不是累加过去调用的 Token 用量，以便空间容量与累计用量不被混淆。
6. 作为提问用户，我希望可完整装载的工具结果保持原文和来源，以便答案可以逐字核验。
7. 作为提问用户，我希望过大的工具结果在装载前被拒绝，以便它不会挤爆下一次模型输入。
8. 作为提问用户，我希望被拒绝的证据不能出现在有效引用中，以便未送给模型的材料不会被冒充为已读证据。
9. 作为提问用户，我希望模型能收到简短的容量反馈，以便它有机会减少返回数量或缩小读取窗口。
10. 作为提问用户，我希望已装入的证据在容量反馈后仍保留，以便模型能基于已有材料回答。
11. 作为提问用户，我希望缩小读取范围由模型决定，以便程序不会通过关键词规则替我选择事实或删除关键步骤。
12. 作为提问用户，我希望 Parent 的原文窗口与引用范围一致，以便未装入的同章节文字不能被自动视为可引用内容。
13. 作为提问用户，我希望减少结果数量后仍过大的单条 Child 得到诚实的容量失败，以便系统不会静默裁剪后声称原文完整。
14. 作为提问用户，我希望每个工具调用都有对应结果或容量反馈，以便多工具调用仍保持合法消息配对。
15. 作为提问用户，我希望缓存命中的结果也按当前输入重新检查容量，以便缓存不会绕过证据和输入预算。
16. 作为多分支问题的用户，我希望各分支按各自输入检查容量，同时共享既有请求调用和时间预算，以便并行执行不会扩大额度。
17. 作为提问用户，我希望容量受阻、调用额度耗尽、请求超时和资料不足能够区分，以便知道本轮为什么未完成。
18. 作为提问用户，我希望后续调整工具请求仍计入已有预算，以便容量反馈不会引入无限重试。
19. 作为维护者，我希望通过稳定的 interface 验证装载、拒绝和回答行为，以便内部函数调整不会让测试失去意义。
20. 作为维护者，我希望工程检查与真实模型质量分别记录，以便 scripted provider 的成功不会改写旧的真实失败。
21. 作为用户，我希望对外容量事件和日志不包含私有提示、原始拒绝载荷或密钥，以便诊断不会泄露私有内容。

## Implementation Decisions

### 已确认的容量语义

- Q1：动态阈值作为证据装载预算生效；完整输入同时受物理上限约束。
- Q2：每次调用检查当前输入，重复证据按当前消息中的实际出现次数计量；不累计历次调用用量。
- Q3：超限结果先拒绝装入，返回容量说明，由模型选择缩小读取范围或基于已有证据回答；无法继续时如实结束。
- 沿用现有 Token 估算方法、动态阈值增长方式和分支迭代含义。估算值不是提供商的精确 tokenizer 结果，展示时不得冒充实测。
- 保留当前默认基数 2000、增长因子 0.9 及既有配置覆盖能力；本功能不调整数值。动态阈值再大也不能越过物理上限。
- 证据预算只计入当前输入中的检索原文文本。提示词、用户问题、工具定义、消息结构及元数据、容量反馈等仍计入完整输入检查。
- 证据占用属于完整输入的一部分，完整输入计量不能再额外加一遍证据预算。调用用量统计继续独立记录。
- 不将本次动态证据预算扩展为入口问题分析或普通会话摘要的新增业务限制；这些调用继续遵守既有完整输入约束。

### module 与 seam

- 上下文装载 module 负责计算证据占用、检查完整候选输入、决定是否装载和维护已读证据登记。它应隐藏这些共同不变量，而不是新增多个转发 module。
- 模型循环继续负责模型语义决策、合法工具调用及循环推进；检索与 Parent 原文读取 module 继续执行明确的只读请求。
- 引用验证只接受已经成功装入的原文范围；完整 Parent 的本地备份、未送出的窗口或被拒绝的工具结果不能因本地存在而取得已读资格。
- 优先使用现有运行 interface 作为测试 seam，不为测试增加公开的低层方法，不引入通用插件框架。
- 保持单一 RAG 包和提示唯一来源。若模型需要容量说明，其消息模板继续由既有提示 module 管理。

### 装载与反馈约束

- 检查针对即将发出的实际输入，包含已有消息、候选工具回复、资源提示和工具定义；不得以固定预留字符数替代最后一次完整检查。
- 一个工具结果中的候选证据应整体接受或整体拒绝，不由程序自动挑选其中几条、截断原文或重新排序以塞入容量。
- 拒绝装入不撤销此前已经成功装入的证据，也不把拒绝结果加入可引用证据登记。
- 多工具回复仍逐一保持调用标识配对。容量反馈本身也必须能装入；若最小合法反馈与已有输入都无法满足物理上限，直接形成明确的容量失败，不追加超限消息继续调用模型。
- 模型可以利用现有 Child 数量参数和 Parent 窗口参数缩小请求。程序不自动代改这些参数，不自动重试同一调用。
- 单条 Child 仍无法装载时允许明确失败；本功能不因此引入新的 Child 分页协议。
- 不能因为每轮阈值增长而自动重放之前拒绝的证据。继续读取需要模型新的明确决策，并遵守原有调用与工具预算。
- 缓存只减少重复读取，不等于证据已被模型接收。每次准备发送缓存结果时都要按当前输入检查容量。
- 多分支按各自真实输入检查；最终汇总保留既有完整输入检查与引用核验，不新增跨分支共享证据容量池。
- 终态沿用已有失败与不足区分：物理或证据容量无法满足、调用额度耗尽、请求超时分别报告；模型已基于可用证据判断不足时仍可返回模型资料不足状态。
- 整次请求上限 300 秒、单次模型等待上限 120 秒及现有模型/工具/分支额度保持；容量反馈、缓存和失败不得重置这些限制。
- 容量观测只包含必要的原因、限额、估算占用、调用标识等安全元数据。保留公开遥测与本地私有诊断的既有区分，不通过删除历史证据或暴露原始载荷来简化实现。

## Testing Decisions

### 已确认的测试 seam

1. 主要行为 seam：现有 AgentGraphService.run。注入 scripted provider、受控检索结果和临时原文存储，从完整问题运行观察模型收到的输入、工具回复、有效引用、最终状态及用量，不断言私有函数调用顺序。
2. 对外契约 seam：现有聊天 SSE 请求入口。只补充必要的容量失败、终态、事件配对及隐私检查，确认后端序列化和现有前端消费兼容；不据此扩展前端功能。
3. 必要的聚焦补充：通过 ModelAgentLoop.run 验证批量工具回复、重复证据和边界输入。新增上下文装载 module 若需要纯计算测试，可使用其明确 interface，但不得以这些测试替代前两类行为检查。

### 行为验收范围

- 完全可装载、恰好到达限额和超出限额均有用例；证据阈值和物理上限应能分别成为拒绝原因。
- 物理上限计算覆盖提示词、问题、工具定义、消息结构、资源提示和实际工具回复；覆盖证据本身可装入但总输入超限。
- 当前消息中的重复证据重复计量；后续调用使用当前快照，不将历次调用用量错误相加。
- 完整接受的结果保持原文、来源和引用；被拒绝结果没有已读资格，不能在后续引用验证中获得通过。
- Parent 分窗读取只使已装入窗口取得引用资格；缓存命中和重复窗口同样遵守实际输入计量。
- scripted 模型收到容量反馈后可以明确选择更小的请求并完成有依据的回答；也覆盖无法缩小的单条 Child。
- 多工具调用中接受、容量拒绝及非法调用并存时，每个调用都仍有正确对应的工具回复。
- 容量反馈自身装不下、反馈后仍无可行输入、额度耗尽和期限到达均有明确终态；不越限重试，不把程序失败写成模型认定资料不足。
- 多分支继续共享请求级调用与时间预算；某分支容量失败不得伪装为全部分支完成。
- 已有无压缩、模型自行选择检索/Parent、题设条件保留、引用修复边界、迟到会话隔离、云端不自动切换和公开日志隐私约束保持。

### Prior art 与证明力

复用现有图运行、模型自主选择检索/Parent、工具标识配对、引用校验、分支部分失败、预算隔离、请求截止时间及日志隐私测试的构造方式。现有“旧阈值不影响循环”的行为断言与本次新规格发生明确变化时，应以新的可观察行为替代，并在报告中解释原因；不能静默删除其他失败或真实验收记录。

工程验收使用 scripted/fake provider 和隔离数据，不访问正式索引，不调用真实模型。真实模型及原失败问题复测需要独立授权、冻结输入和另存首次结果；工程通过不能证明模型一定会选择合适窗口，也不能宣称三次历史容量失败已解决。
