## 拆分原则与顺序

每个任务交付一条可从现有运行 interface 验证的行为链，包含必要的生产实现、消息/事件契约和测试。没有单独的“建 module”“改 schema”“补测试”横向任务，也不为拆分而新增 UI。

T1 先建立共同装载行为；T2、T3 分别在此基础上处理原文窗口和复合回复；T4 完成这些行为在多分支请求中的对外交付。T2、T3 没有彼此的业务阻塞关系，但可能修改同一 module，实施时仍须按获准范围协调，不能把可并行依赖图当作并行修改授权。

依赖图：T1 → T2；T1 → T3；T2、T3 → T4。

每个任务的报告与验收都是独立停止点。对整体方案笼统说“执行”时，仍只实施第一个尚未完成的任务，不自动完成后续任务。

## T1：Child 搜索超限后反馈容量，并允许模型缩小请求继续回答

**Parent：** 规格 #1。

**Blocked by：** 无，可先开始。

**What to build：** 用户提交单分支问题，模型选择 Child 搜索。工具返回先经过统一的上下文装载 module 检查，完整可装入时保留原文与引用；装不下时返回简短容量反馈，模型可自行减少搜索数量或使用已装入证据回答。用户最终得到可核对答案或明确的失败原因。

**验收条件：**

- [x] 证据动态预算与完整输入物理上限都生效，维持现有估算算法、阈值增长与默认配置；能分别构造只超证据预算和只超物理上限的情况。
- [x] 每次使用当前输入快照；重复证据按实际出现次数计量，不累计历次调用用量，不在完整输入上重复加算证据占用。
- [x] 工具结果中的证据整体接受或拒绝；接受时保留原文，拒绝时不进入模型消息和已读引用登记，已有证据不被删除或裁剪。
- [x] 模型收到与该工具调用配对的容量反馈后，可明确选择更少的 Child 结果继续完成回答；程序不得自动改参数或重放被拒绝结果。
- [x] 单条 Child 无法缩小时允许明确失败，不新增 Child 分页工具，不把容量受阻写成模型确认资料不足。
- [x] 下一次模型调用前检查完整实际输入，包含消息结构、工具定义、资源提示和容量反馈；反馈本身也装不下时不调用模型。
- [x] 容量调整继续消耗已有工具/模型额度并服从同一截止时间；额度耗尽、时间到达与容量失败分别如实结束。
- [x] 通过已确认的图运行 interface 和必要的 SSE 契约，以 scripted provider、临时数据验证完整行为；公开结果只包含安全容量元数据，既有单分支无压缩及模型决策行为保持。

上述勾选表示 T1 工程行为已验证，不代表用户阶段验收或真实模型质量通过；完整套件保留两项既有提示断言失败。首次宽范围回归误纳入真实 FastEmbed 测试及后续保护脚本误拦均在 T1 报告保留，不能把所有运行统称为 fake-only。本轮没有关闭或更新 GitHub issue，也不解除后续阶段的用户授权边界。

**独立演示：** 第一次搜索结果过大；模型收到容量反馈后显式减少结果数，最终引用已装入原文完成回答；另展示无法装载时的明确终态。

**范围：** 完成最小可用的共同装载 module 与 Child 单工具调用闭环。必要的局部整理随此行为完成，不夹带 P2/P3 重构。Parent 窗口身份、同一决策内多个工具回复和跨分支交付分别由后续任务覆盖。

## T2：Parent 分窗读取与引用范围保持一致

**Parent：** 规格 #1。

**Blocked by：** T1。需要复用已生效的容量准入、反馈和已读证据登记规则。

**What to build：** 模型在 Child 搜索后选择读取 Parent。Parent 原文窗口必须完整通过容量检查；窗口过大时模型可用现有参数缩小读取。答案只能引用本次实际装入过的原文范围，不能因本地保有完整 Parent 就引用未读取部分。

**验收条件：**

- [x] Parent 候选窗口接受或拒绝遵守 T1 的两种容量限制；程序不自动截取、摘要或挑选原文。
- [x] 被拒绝窗口不取得已读资格，先前已装入窗口不丢失；后续模型显式选择更小窗口后可以继续回答。
- [x] 引用核验仅接受已装入范围，拒绝引用完整 Parent 中未送给模型的文字；多个已装入窗口仍保留可核对的来源和范围。
- [x] Parent 原文读取缓存不等于窗口已装入；缓存命中的每个新窗口重新检查当前容量。
- [x] 同一窗口重复出现在当前输入时计入重复占用，既有 Parent 读取授权及工具标识配对保持。
- [x] 经图运行 interface 及必要 SSE 契约，展示缩小窗口后有依据回答、未读范围引用被拒绝和缓存仍受容量约束；不访问正式文档或真实模型。

T2 勾选仅表示工程行为已验证，待用户验收；完整回归为 614 通过、两项既有失败、两项真实嵌入相关测试排除。全部 T2 后端运行使用已修正的真实模型/连接保护。GitHub issue 和原生阻塞关系保持原状，本轮没有关闭 #2/#3 或自动推进后续任务。

**独立演示：** 模型首次请求的 Parent 窗口过大，收到反馈后主动缩小窗口并引用已读文字；尝试引用其他窗口的文字不能通过核验。

## T3：多工具回复与缓存命中仍满足同一输入容量

**Parent：** 规格 #1。

**Blocked by：** T1。需要复用共同容量准入和反馈行为；不以 T2 的 Parent 窗口实现为前置条件。

**What to build：** 同一分支的模型决策可包含多个工具调用。工具回复中即使混有完整结果、容量拒绝和非法调用，模型仍收到合法配对且整体可装入的消息。缓存或重复请求也不能绕过计量。

**验收条件：**

- [x] 同一模型决策内每个工具调用都有对应的完整结果或简短反馈，不遗漏或错配调用标识；多个回复形成的下一次完整输入也满足物理上限。
- [x] 同批次的接受、容量拒绝与非法调用可以同时存在；每个结果中的候选证据仍整体接受或拒绝，且拒绝项不取得已读资格。
- [x] 为尚未回复的调用形成最小合法反馈后，整体仍无法装载时明确结束，不用删除已装入证据、发送非法消息或超限调用来继续。
- [x] 当前输入中重复出现的 Child 载荷按实际份数计量；缓存命中只减少读取，不免除容量检查，也不混淆累计 Token 用量。
- [x] 模型再次选择同一请求时使用当前预算判定，阈值增长不触发程序自行重放；次数、工具额度与截止时间不重置。
- [x] 以现有图运行 interface 为主，必要时通过模型循环运行 interface 聚焦验证批量配对及容量边界，并检查公开事件的调用标识、缓存来源与失败原因；不依赖私有方法的调用顺序。

## T4：多分支容量受阻时，正确交付部分回答或失败

**Parent：** 规格 #1。

**Blocked by：** T2、T3。此任务验收组合 Child、Parent 窗口、复合工具回复与缓存的完整多分支请求；T1 已通过传递依赖包含在内。

**What to build：** 用户提出多分支问题，各分支按自己的当前输入检查容量，同时共享现有请求调用与时间预算。部分分支无法继续时，用户得到保留成功内容的部分回答或明确失败，最终汇总、引用与 SSE 终态保持一致。

**验收条件：**

- [x] 各分支的证据占用、拒绝结果与已读登记相互隔离；不引入新的跨分支共享证据容量池。
- [x] Child、Parent 分窗、同一决策的多工具回复及缓存行为在组合请求中仍满足 T1–T3 的规则；拒绝证据不得经分支归并进入有效引用。
- [x] 某分支容量失败不能被汇总冒充为全部完成；能够交付已有成功内容时保留内容并如实标为部分回答，全部执行失败时不伪装为模型资料不足或正常成功历史。
- [x] 最终汇总继续检查完整输入与已读引用，不通过放大窗口、摘要或删除已读证据绕过限制；无法汇总时给出明确失败。
- [x] 入口、分支、反馈后的继续调用、汇总及现有可选调用继续共享原请求额度和截止时间；保留预算槽隔离与迟到会话保护。
- [x] 经图运行 interface 和聊天 SSE 入口验证最终答案、引用、失败原因、用量和单一终态；核对现有前端消费兼容和公开遥测脱敏，不新增 UI 功能。
- [x] 在隔离工程回归中记录既有失败与本次变化，按新规格解释旧阈值断言的调整；不删除失败证据，不把工程结果当成真实模型或旧失败题已通过。
