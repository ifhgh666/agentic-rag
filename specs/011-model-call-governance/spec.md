# Feature Specification: P2 模型调用治理与诊断交付一致性

**Feature Branch**: 未创建；本轮仅生成规格。

**Created**: 2026-10-21

**Status**: A–D 工程完成、待用户验收；最终组合与回归见 [D 报告](phase-d-report.md)，797 passed / 2 failed / 2 deselected，两项既有提示词断言失败保留。[tasks.md](tasks.md) 的勾选不代表全绿、用户验收或真实模型质量通过。

**Input**: 用户要求“开始p2”，承接 P1 完成后的原架构改进路线。P2 指调用治理整理和诊断写入一致性，不是旧功能中同名的用户故事优先级。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 每次模型调用遵守同一请求约束 (Priority: P1)

用户提出问题后，无论系统正在理解问题、执行分支、修正答案、汇总还是整理会话，都能在原有次数、输入容量和时间限制内完成或明确结束。维护者增加或调整调用时，不必分别记忆多个调用位置的治理规则。

**Why this priority**: 这些约束目前由多个调用者分别维护，修改一处不能保证其他路径一致。本故事中的 P1 是本规格内部顺序，不代表重开已完成的架构 P1。

**Independent Test**: 用受控答复及可控时间，对各现有调用路径分别构造输入过大、额度不足、模型异常和迟到结果，观察是否发起调用、最终原因、次数及历史是否一致；不需要真实模型。

**Acceptance Scenarios**:

1. **Given** 当前完整输入超过原物理限额，**When** 准备调用，**Then** 不发送超限请求，不消耗尚未实际准入的模型调用额度，返回容量原因。
2. **Given** 当前分支或请求调用额度已耗尽，**When** 任一必要调用准备执行，**Then** 不再调用模型，保留预算失败及已发生用量；可选摘要延后，不抢占回答和汇总额度。
3. **Given** 请求总期限仍在持续计时，**When** 反馈后的继续、答案修复或汇总开始，**Then** 只能使用剩余时间和原有额度，不重置期限；迟到答复不改变已结束结果或正常历史。
4. **Given** 一次调用失败，**When** 返回事件和统计，**Then** 请求、分支、调用标识、耗时和用量来源可追溯，安全失败原因不包含异常中的私有内容。
5. **Given** 现有结构格式兼容机制需要再次发送，**When** 发生允许的格式回退，**Then** 沿用原有逻辑调用计费语义和总期限，并对变更后的完整输入重新确认容量；不增加语义重试或切换模型。

### User Story 2 - 诊断保存失败不改写已经完成的问答 (Priority: P1)

当问答已经得到合法结果时，用户仍能收到该结果，即使本地诊断保存遇到目录不可写、序列化失败或写入失败。维护者能区分“问答失败”和“诊断缺失”，普通事件与本地私有诊断保持各自范围。

**Why this priority**: 当前诊断写入发生在图执行与会话处理之后；保存失败仍可能使用户收到流水线失败，与内部已经完成的历史不一致。

**Independent Test**: 对同一受控问答，分别关闭诊断、正常保存、注入保存失败或阻塞，比较答案、引用、终态、用量和历史；单独检查安全诊断状态及保存文件的完整性。

**Acceptance Scenarios**:

1. **Given** 图执行已经完成且请求仍可交付，**When** 诊断目录或文件写入失败，**Then** 答案、来源、问答状态和用量与未发生该故障时一致，用户得到一个终态，历史不因诊断故障出现相反结论。
2. **Given** 图执行本身失败，**When** 诊断同时失败，**Then** 保留原问答失败原因，不由诊断异常覆盖。
3. **Given** 诊断关闭，**When** 请求结束，**Then** 不创建诊断目录或文件，问答行为保持。
4. **Given** 诊断保存中断或同一标识已经存在记录，**When** 检查最终记录，**Then** 成功发布的记录完整可读，原记录不被截断或静默覆盖，失败不能被登记为保存成功。
5. **Given** 诊断写入不能及时完成，**When** 请求继续交付，**Then** 诊断不阻塞主要答复；请求已超时时仍保留超时终态，不追加成功终态，也不让迟到任务修改正常历史。

### Edge Cases

- 缓存命中不执行模型，因此没有虚构调用；未命中或修复后的下一次真实调用仍检查当前完整输入。
- 结构约束和工具定义也占输入；提供商需要增加格式约束时不能绕过容量检查，不能重复把证据占用加到完整输入上。
- 没有提供商实测用量时标记估算；调用前拒绝、提供商失败和成功调用不得混算为同一状态。
- 某分支额度耗尽、另一个仍有额度时，保留 P1 的分支隔离、成功内容和汇总槽。
- 没有外部请求上下文的独立服务调用不得成为生产绕过治理的入口；具体适配方式在技术方案中确定，不启用旧式检索决策。
- 诊断告警的记录也可能失败；记录告警失败不能再把已完成问答改成失败，不能递归记录造成循环。
- 诊断序列化失败、目标目录被占用、写入中断、重复标识和慢写均需要独立故障证据。
- 原问答超时与可选摘要迟到时，继续按既有规则恢复历史和待澄清状态；不能借诊断改动放宽期限。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 所有现有生产问答调用及仍对外提供的独立模型服务调用必须遵循同一套可核验治理约束；不能由调用者遗漏某项校验而绕过。覆盖问题分析、分支循环、答案修复、最终汇总、普通答案生成、既有检索改写接口和可选会话摘要；不恢复当前未接入图的旧逻辑。
- **FR-002**: 每次实际调用前必须检查当前完整输入，沿用既有 Token 估算方法和有效物理限额，包含消息、工具定义和结构约束。提供商兼容机制改变发送内容时也必须受该限额约束。
- **FR-003**: 容量或期限不满足时不得发送模型请求；必要的调用准入通过后，按原语义原子预占一次逻辑调用额度。已发起调用失败也必须如实计入，不回退为未调用。
- **FR-004**: 沿用当前默认单请求 8/12 次模型调用、1/2/3 分支的 5/4/3 次分支额度、工具额度和既有节点/回答/汇总/修复/摘要槽规则，保留配置覆盖能力，不扩大额度。缓存不计作真实模型调用。
- **FR-005**: 整次请求继续使用同一个不超过 300 秒的截止时间；单次模型等待不超过当前配置上限（默认 120 秒）及请求剩余时间。调用完成后也检查期限，迟到结果不能发布为成功或写入正常历史。
- **FR-006**: 成功和失败调用均提供请求、逻辑调用及适用分支标识、调用用途、耗时和实际可得用量；估算与提供商实测明确区分。调用前拒绝不得伪造提供商成功答复或次数。
- **FR-007**: 调用层只负责容量、额度、期限、提供商执行和调用观测；问题语义、工具选择、答案解析、引用修复决定及会话摘要内容校验继续由各自业务负责，不增加重试或语义兜底。
- **FR-008**: 保留现有提供商选择和格式兼容语义。结构格式回退仍属于原逻辑调用，不能重置预算或整次等待；如记录底层尝试次数，须与逻辑调用次数明确区分，不改写既有计费字段含义。
- **FR-009**: P1 的动态证据预算、当前输入计量、整体接受/拒绝、Parent 实读范围、批次配对、缓存重检和多分支部分交付必须保持；不能把统一调用治理变成新的共享证据池、自动压缩或裁剪。
- **FR-010**: 诊断是可选附属记录。关闭时不写入；开启时保存成功、失败或跳过的诊断状态必须与问答状态区分。诊断失败不得覆盖问答答案、来源、原因、调用用量或已经合法确定的历史。
- **FR-011**: 只有完整可读的诊断记录才能声明保存成功；不能以半截内容替代正式记录，不能静默覆盖同一标识下已有证据。异常处理不能删除原始失败或历史报告。
- **FR-012**: 诊断保存及其告警不得阻塞主要问答交付，也不得延长请求总期限；不及时可完成时安全跳过或延后记录。迟到诊断任务只能处理对应记录，不能再发布问答事件或修改会话。
- **FR-013**: 对外诊断状态只含必要标识、安全错误类别和状态；不得暴露完整提示、历史、原始候选、拒绝证据、密钥、异常正文或私有文件路径。私有记录保持既有本地访问范围，不新增用户入口、扩大记录正文或把私有推理写入新字段。
- **FR-014**: 保持现有聊天事件名称、终态、来源和用量字段的消费兼容，每个请求只有一个终态。诊断状态如需对外呈现，只复用现有安全观测能力，不新增 UI 功能；必要的增量字段不得改变旧字段含义。
- **FR-015**: 工程验证使用 scripted/fake provider、假传输、受控时间、临时存储和隔离数据，并复用 P1 的真实模型保护。没有真实模型授权，不访问正式文档、索引或真实模型，不把工程结果改判为质量验收。
- **FR-016**: 维护者通过同一个调用治理 interface 可测试公共约束；调用者和测试不需要借用模型循环的私有执行方法才能获得保护。诊断记录有独立可替换的存储 seam，故障可在现有问答/SSE interface 验证。

### Key Entities *(include if feature involves data)*

- **请求执行上下文**：请求/分支身份、原截止时间及共享调用与工具额度，生命周期不因后续调用延长。
- **逻辑模型调用**：用途、准备发送的输入和约束、准入与执行状态、结果或安全失败类别；底层格式尝试不等于新增逻辑调用。
- **调用记录**：可追溯身份、时间、用量来源及本地诊断关联；公开投影不含原始私有输入。
- **问答结果**：答案、来源、问答状态、原因、用量及对应会话处理结果，不能由诊断写入故障任意改写。
- **诊断保存结果**：与请求身份关联的 saved / failed / skipped 等记录状态及安全原因，独立于问答成功或失败。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对范围内每种调用用途，输入超限、额度耗尽、期限耗尽的受控用例均能阻止不允许的请求，违规发起次数为 0；所有已发起逻辑调用均可追溯且计数一致。
- **SC-002**: 对诊断关闭、成功、不可写、序列化失败和写入失败的配对用例，用户得到的问答正文、来源、状态、原失败原因和用量 100% 与基准一致，各只有一个终态。
- **SC-003**: 慢诊断不阻塞答复；各超时/迟到用例均在原请求边界结束，之后新增成功终态和正常历史污染次数为 0。使用可控阻塞与时钟证明，不以极短墙钟耗时当质量指标。
- **SC-004**: 所有声明保存成功的记录均完整可读；写入中断及重复标识用例对原记录的破坏次数为 0；公开遥测中预置私有内容 sentinel 的泄露次数为 0。
- **SC-005**: P1 的已批准工程行为继续通过相关隔离回归；完整回归明确列出实际结果及既有失败，不删除或修改旧真实失败来达标。
- **SC-006**: 验收证据能按请求关联问答终态、实际调用及诊断状态；能够区分未调用、调用失败、诊断缺失和模型资料不足，不用单一泛化失败替代。

## Assumptions

- P1 的 T1–T4 工程已经完成；真实模型复验是独立可选后续，不是本规格的前置工程任务。
- 诊断采用“尽力保存、故障不改变已完成问答”的默认取舍。它不是必须先写入成功才允许交付答案的合规审计账本；本稿没有新增该业务要求。
- 规格、规划与任务拆分已交付；C 后用户要求“继续”，本轮仅实施 D。工程结果见阶段报告；不运行真实模型、不发布 GitHub issue，不自动进入 P3。
- 核心职责集中化的实现形式、准备输入的具体契约、独立调用适配方式、诊断存储与慢写处理方式由技术方案解决，不在本规格中预先绑定类名或文件拆法。
- P3 失效依赖清理、旧检索决策恢复、提示业务规则、模型或依赖升级、扩大 Token 窗口/额度/超时、真实题集评测、前端重设计、生产部署均不在范围。
- 保留既有本地/兼容提供商能力，未获授权不切换到云端；普通历史摘要不是 RAG 证据摘要，不恢复被禁止的证据压缩。
- 既有两项提示措辞断言失败、真实问答失败与历史执行偏差继续独立保留。本稿的需求质量通过不等于产品实现或测试通过。
