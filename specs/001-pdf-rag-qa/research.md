# 研究记录：PDF RAG 知识库问答

**功能**：`001-pdf-rag-qa`  
**日期**：2026-09-22

## 决策摘要

| 领域 | 决策 | 原因 | 未采用的方案 |
|---|---|---|---|
| PDF 解析 | 通过独立的 `PdfParser` 适配器使用 PyMuPDF；输出带页码和标题元数据的 Markdown 风格文本 | V1 只处理文本型 PDF，PyMuPDF 支持本地运行、速度快且不依赖远程服务 | OCR 和图像理解明确不在 V1 范围内；仅在浏览器侧解析会使后端行为不稳定 |
| 父子分块 | 保留章节作为父级上下文单元，再使用 `RecursiveCharacterTextSplitter` 将父级内容切成可检索子单元 | 父级检索能保留完整上下文，子级检索能提高匹配精度 | 单一尺寸的分块会丢失章节语义；V1 不需要完整的语义分块方案 |
| 向量嵌入 | 将 `sentence-transformers` 封装在 `EmbeddingService` 后面；默认模型为 `Qwen/Qwen3-Embedding-0.6B`，模型名可配置 | 将模型加载和向量维度隔离在服务中，便于测试和更换提供商 | 在 API 路由中直接写死嵌入调用会增加测试和替换难度 |
| 向量检索 | 使用向量归一化后的 FAISS `IndexFlatIP`，配合 JSON 元数据侧车文件 | 归一化后的内积可以透明地实现余弦相似度，并且删除后容易重建 | 远程向量数据库会增加 V1 明确排除的运维范围 |
| 持久化 | 在 `backend/data/` 下保存原始 PDF、提取文本、父子元数据、向量索引和 JSONL 日志 | 文件存储符合单服务本地部署方式，也便于审计删除结果 | V1 不需要并发多节点写入，因此暂不引入 SQLite/PostgreSQL |
| 答案生成 | 通过 `AnswerGenerator` 使用 OpenAI 兼容客户端，并采用只允许使用上下文的提示词 | 支持文档中约定的模型提供商，同时不绑定某一家厂商 | V1 不引入联网搜索、代理循环或多轮记忆 |
| 质量评估 | 使用结构化评估适配器返回相关性、忠实性、完整性、总体分数和原因 | 评估结果可见且可机器读取，同时允许后续接入模型评估器 | 不能因为分数低而在后台隐藏重试或二次检索 |
| 进度传输 | 从同一个请求级流水线通过服务器推送事件流发送有类型的进度事件 | 单向进度已经足够支持单轮浏览器流程，并能让界面实时显示阶段 | V1 不需要双向通信，因此不引入 WebSocket |
| 身份认证 | 一个配置中的管理员、密码哈希、JWT Bearer 令牌和受保护路由 | 满足单管理员边界，同时避免把密钥放进源码 | 注册、角色和外部身份提供商延后 |
| 日志 | 使用包含 `request_id`、级别、模块、消息和错误详情的 JSONL 追加日志 | 本地容易检查、过滤和关联 | V1 本地范围不需要完整的可观测性平台 |

## 技术结论

### PDF 解析和失败处理

解析器必须拒绝非 PDF 文件、空文件、损坏文件以及无法提取有效文本的 PDF。
提取结果应保留页边界，以便来源预览在可用时显示页码。解析器属于流水线服务，
不能把逻辑放进路由中；它应返回类型明确的结果或用户可理解的失败原因。

### 分块模型

源文本首先进行规范化，并在能够识别标题时按标题分组。每个父级单元携带文档
ID、源文件名、章节标题、页码范围和完整文本。子级单元携带父级 ID，并且只有
子级记录会被建立向量索引。任何子级都不能脱离父级存在。

### 检索和上下文组装

检索器只对问题生成一次向量，搜索 ready 状态索引，按照配置的最低分数过滤，
降序排序，并且默认最多保留 top-k 条结果。加载父级文本前先去重父级 ID。上下文
构建器强制执行最大上下文长度，并为每个上下文块标注文件名和章节。

### 提供商边界

模型和嵌入实现通过依赖注入放在接口之后。应用可以在没有真实模型提供商的情况
下启动，并运行解析器、分块和检索测试。未配置提供商时，答案生成和评估应返回清晰、
可追踪的配置错误；如果需要本地冒烟测试，可以显式启用确定性开发适配器，但不得
把开发结果伪装成真实模型质量。

### 删除和索引一致性

删除采用类似事务的顺序：先让文档不可用，删除原始文件和派生文件，删除全部
元数据记录，根据剩余 ready 子级记录重建向量索引，最后完成删除操作。如果重建
失败，服务必须保留原有 ready 元数据并记录失败，不能悄悄继续使用过期索引。

### 进度和关联关系

流水线在请求收到时创建唯一 `request_id`。每个阶段发送开始和完成事件，并记录
状态与耗时；每条日志都使用同一个 ID。SSE 接口要在任何耗时的模型处理前发送
初始 received 事件，并发送最终 complete 或 error 事件。

## 风险与缓解措施

- 本地嵌入模型下载可能较慢或不可用：采用延迟加载，提供清晰的就绪/配置错误，
  并使用假的嵌入器进行测试。
- 大型 PDF 可能超过上下文预算：在各边界执行子级、父级和上下文限制，并仅在契约
  允许的地方报告截断。
- 失败上传不能破坏 ready 文档：先在文档专属临时目录中处理，所有阶段成功后再
  发布元数据和索引变化。
- JSONL 日志可能无限增长：提供结果数量限制；日志轮转和保留策略作为 V1 之后的
  运维任务记录，不在 V1 中隐藏日志。

## 宪章检查点

研究结果确认，当前适配器、文件存储和请求级流水线符合五项项目宪章原则，
不需要申请范围例外。
