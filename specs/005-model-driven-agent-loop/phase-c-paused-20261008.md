## 2. 现在的流程是什么

1. 用户发出问题，问题分析模型判断指代、是否需澄清、是否拆成多个问题，并提出检索用的问题表述。原始问题及题设条件另外保留，不再用原问题覆盖有效的模型改写。
2. 每个分支把完整问题、已有工具返回和剩余资源交给模型。首轮要求模型自己请求检索；没有实际检索就给终态时，程序反馈协议错误，不代替模型发起搜索。
3. 模型可以请求`search_child_chunks`搜索，或者请求`retrieve_parent_chunks`读取已出现的Parent。实际向量/BM25检索和排序仍由现有检索器执行。
4. 程序检查工具参数、已知Parent、权限状态和资源限额，执行请求，并按`tool_call_id`回传每条工具结果或错误。结果数、片段长度、型号字符串不再决定下一步。
5. 模型读到结果后再次决定继续搜索、读章节、回答、部分回答或说明具体资料缺口。
6. 模型回答中的引用须对应实际证据ID和原文片段。校验失败最多给一次修正机会；程序不再自动拿原文覆盖模型答案。单分支直接采用模型回答，多分支交给模型汇总。
7. 最终记录答案、状态、模型调用、工具调用、耗时及事件关联。前端按实际记录回放执行过程，不把这些日志显示成实时私有思考。

**模型负责语义决策，程序负责执行边界。** 程序仍然控制调用次数、时间、上下文容量、工具白名单和引用格式，这些边界并未删除。

## 3. C阶段已写入的内容

- **答案与原文分开。** 取消短答案自动扩展成整段原文、流程答案由原文覆盖、错误引用ID自动重映射等旧行为。保留模型结论，原文作为单独依据。
- **题设数字可以参与判断。** 用户的195 V、300 ms、65℃等数字无需逐字出现于文档。模型可区分文档事实、用户条件和推导结果；明确声明的文档事实数字须对应所引用的数字。
- **保留原始条件。** 检索改写可更简短，回答模型仍会收到完整题设。已有澄清、独立新题、线程隔离和历史摘要行为一并回归。
- **运行失败与资料不足区分。** 引用失败、无效JSON、预算、超时、模型不可用和索引未就绪有对应原因；运行失败不写成普通成功问答。
- **工具消息与事件可关联。** 多工具逐条回传，缓存和错误有记录，模型动作与程序拒绝执行有不同来源；补充了分支、模型调用、决策、工具调用的ID。
- **Parent按原文窗口读取。** 默认1600字符，可由模型按`next_offset`继续读。完整原文保留于本地证据注册表；分页用于限制上下文容量，不按词面相关性裁切答案。
- **窗口和期限检查。** 模型循环、问题分析、历史摘要按配置限制输入；只读工具等待受请求剩余时间限制。
- **前端用语调整。** 原来的“保留的证据”改为“检索候选”，显示模型/程序来源、分支和“执行后回放”；部分回答及资料不足终态正确清除已解决待办。
- **诊断保存在本地。** 原始模型输入与返回保存于本地日志文件，公共事件不包含完整提示词或候选正文。原始输入调试接口因访问范围审查被拒，未添加该接口。

数值和步骤的语义正确性仍标为`not_evaluated`。上述引用及声明校验不等于自动证明整段答案正确，也不能防止模型遗漏步骤。
