# Feature Specification: RAG 八文件收敛

**Created**: 2026-10-22
**Status**: A 工程完成、待用户验收，见 [报告](phase-a-report.md)
**Input**: 用户纠正最终目标为截图八个实际文件，随后明确“继续”；承接此前直接执行的偏好，本轮完成必要设计、合并、隔离验证和报告。

## User Scenarios & Testing

### User Story 1 - 维护者从八个入口理解完整 RAG (Priority: P1)

维护者希望目录接近所给截图，相关能力实际合并到八个源文件，仍保留现有问答、独立调用、安全与可观察性。

**Why this priority**: 用户明确的最终组织目标；仅减少两三个文件不满足该目标。
**Independent Test**: 核对实际源文件集合与能力迁移清单，并通过受控问答、独立调用和工程回归证明结果保持。

**Acceptance Scenarios**:

1. **Given** 当前所有 RAG 能力，**When** 收敛完成，**Then** 目录仅八个指定源文件，无转发文件、隐藏实现包或动态旧模块注册。
2. **Given** 正常单问、多分支、澄清、修复、摘要、预算和超时场景，**When** 执行受控回归，**Then** 答案、来源、事件、用量与失败处理保持既有契约。
3. **Given** 独立证据、模型、索引或查询调用者，**When** 按迁移表使用新入口，**Then** 原能力和调用参数/结果保持。
4. **Given** 原工程与真实问答失败，**When** 交付，**Then** 原始记录保留，未运行的真实测试不记为通过。

### Edge Cases

- 共享名称、类型注解与循环依赖不能通过吞异常、动态模块别名或删功能规避。
- 纯数据、状态存储、模型摘要分开归属，避免低层引用图/节点。
- 原 monkeypatch 调用点随导入迁移；保留断言含义与测试隔离。
- 正式数据、配置、运行中服务与真实模型不用于本轮验证。

## Requirements

### Functional Requirements

- **FR-001**: RAG 仅保留 __init__、edges、graph、graph_state、nodes、prompts、schemas、tools 八个源文件，保留现有全部能力。
- **FR-002**: 迁移应用、脚本及测试调用，旧模块入口直接移除；不增加转发文件或动态旧模块兼容。
- **FR-003**: 保留内部类/函数的职责、参数、返回和算法；必要调整限于归属、导入、名称冲突及组织变化所需的引用。
- **FR-004**: 保持原文、来源、模型动作、输入准入、共享预算、租约、单一期限、迟到隔离、历史和诊断交付约束。
- **FR-005**: 保持生产提示/结构内容、聊天协议与前端行为，不增加功能、依赖或模型切换。
- **FR-006**: 以合并前后完整隔离后端回归和必要结构审计验证，保留原失败；禁止真实模型、真实嵌入、网络和正式数据操作。
- **FR-007**: 保存归属表、基线、迁移证据、命令与报告，单阶段交付后停止。

### Key Entities

- **能力归属条目**：旧模块/符号、新入口和必要引用迁移。
- **行为基线**：合并前受控问答和工程检查结果。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 实际 RAG 源文件集合与目标八文件完全一致，旧模块直接运行导入为零。
- **SC-002**: 全部原生产顶层能力有迁移记录，无未经授权的能力删除。
- **SC-003**: 隔离完整回归无新增产品失败，既有失败与未测项单列。
- **SC-004**: 真实模型、网络和正式数据操作为零，交付报告可核对。

## Assumptions

- 沿用现有 rag 包名；截图表达文件布局，不另建 rag_agent 包。
- 收敛包含旧模块路径移除，仓库外调用者按迁移表改导入；原方法能力保持。
- 大文件内以明确类/函数和职责分区组织；不承诺性能或真实质量提升。
