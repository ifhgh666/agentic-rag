# Feature Specification: 云兼容端点的结构化输出兼容

**Feature Branch**: `009-cloud-provider-compat`

**Created**: 2026-10-15

**Status**: Draft

**Input**: User description: "在云端兼容提供商上增加结构化输出回退（严格 JSON Schema → 通用 JSON 模式），并把 schema 要求注入提示词；同时消除远端压缩返回导致的云端调用整体不可用。目标是让用户自行配置的云兼容端点能真正完成一次完整问答。"

**授权依据**：2026-10-15 用户在“云端路径怎么处理”中选择“授权我做 provider 级修复（推荐）”，并要求按项目流程新建规格并单独记录。本功能不属于 008 展示层重构。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用自配云兼容端点完成一次问答 (Priority: P1)

用户把系统配置为使用自备的云端兼容端点（自带地址、密钥与模型名），提交一个知识库问题，期望像使用本地模型一样得到带来源的回答，而不是收到“模型不可用”。

**Why this priority**: 这是用户切换端点后的首要目标。当前该路径整体不可用：任何一次调用都会失败，问答从未开始，用户无法判断问题出在配置、知识库还是系统。

**Independent Test**: 将系统配置为云兼容端点，提交一个知识库内有依据的问题，观察是否返回非空回答与来源，且过程中没有把失败原因写成“模型不可用”。

**Acceptance Scenarios**:

1. **Given** 已配置可用的云兼容端点与知识库索引就绪，**When** 用户提交一个知识库内有依据的问题，**Then** 系统返回非空回答与至少一个来源，且端到端在既定的整次请求期限内完成。
2. **Given** 同一配置，**When** 入口问题分析执行，**Then** 分析结果仍是可被既有校验接受的结构化结果，不出现“输出非法”类的失败原因。
3. **Given** 端点明确拒绝系统首选的结构化输出模式，**When** 系统执行同一次问答，**Then** 系统改用该端点支持的结构化模式完成该次调用，不向用户报“模型不可用”。

---

### User Story 2 - 失败原因可区分 (Priority: P1)

当真实原因是“端点不支持该能力”“密钥或额度问题”“网络/压缩处理问题”或“模型确实输出了非法内容”时，用户与运维能在请求记录中分辨这些情况，而不是统统看到同一个原因。

**Why this priority**: 当前所有调用异常都被归为同一个失败原因，导致排查方向错误（用户曾据此误判为额度用尽）。可区分的原因是后续任何修复的前提。

**Independent Test**: 分别构造“端点拒绝结构化模式”“端点返回错误状态”“模型输出非法内容”三类情形，检查请求记录中的失败原因是否彼此不同且指向真实原因。

**Acceptance Scenarios**:

1. **Given** 端点拒绝首选结构化输出模式，**When** 该次调用结束，**Then** 记录体现“端点能力不支持”而非“模型输出非法”。
2. **Given** 模型返回的内容无法通过结构校验，**When** 该次调用结束，**Then** 记录体现“输出非法”，且不声称端点不可用。

---

### User Story 3 - 本地路径行为不变 (Priority: P2)

继续使用本地模型或显式测试模型的用户，升级后不应观察到任何行为变化。

**Why this priority**: 项目默认本地优先；任何为云端引入的改动都不能污染默认路径，否则会破坏既有验收基线。

**Independent Test**: 运行既有的本地与假模型测试与回归，确认其结论与修复前一致。

**Acceptance Scenarios**:

1. **Given** 配置为本地模型，**When** 执行既有的问答与分析场景，**Then** 其行为、事件与失败原因与修复前一致。
2. **Given** 配置为显式测试模型，**When** 运行既有工程检查，**Then** 全部结论保持通过。

---

### Edge Cases

- 端点支持首选结构化模式时：不得发生任何回退，调用次数不得增加。
- 端点既不支持首选模式、也不支持通用 JSON 模式时：必须给出可解释的失败原因，而不是无休止重试；同一逻辑调用最多尝试两次。
- 单次调用预算或整次请求期限将尽时：不得因为回退而突破既有上限；剩余时间不足时直接按既有超时/预算规则结束。
- 远端以压缩方式返回内容时：必须能正常取得内容；不得把客户端解压环节的失败冒充为“模型不可用”。
- 端点返回空正文但带有内部推理内容时：必须按既有“空正文”规则处理，不得把内部推理当作答案。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 能在配置为云兼容端点时完成一次完整问答（入口分析、检索决策、答案生成），不因端点不支持系统首选的结构化输出模式而整体失败。
- **FR-002**: 当端点拒绝首选结构化输出模式时，系统 MUST 自动改用该端点支持的通用 JSON 模式重试同一逻辑调用，且同一逻辑调用最多尝试两次。
- **FR-003**: 采用回退模式时，系统 MUST 让模型仍能获知所需输出的字段与类型要求，使返回内容仍由同一结构校验判定，不得降低校验强度。
- **FR-004**: 系统 MUST 在请求记录中记录本次调用实际使用的结构化输出模式以及是否发生回退，且不记录提示词正文、密钥或私有推理。
- **FR-005**: 端点能力不足与模型输出非法 MUST 是可区分的失败原因，前者不得记为后者，也不得记为“模型输出非法”。
- **FR-006**: 系统 MUST 在远端以压缩方式返回内容时正常取得并使用该内容，不得因客户端解压环节失败而把整次问答判为模型不可用。
- **FR-007**: 本地模型路径与显式测试模型路径的行为 MUST 保持不变（事件、失败原因、调用次数与既有测试结论一致）。
- **FR-008**: 本功能 MUST NOT 提高既有的整次请求期限、单次模型等待上限或请求级调用预算；回退不得使云端调用突破这些边界。
- **FR-009**: 失败原因、错误文案与对外事件 MUST 继续脱敏，不得向用户或日志暴露端点密钥、完整提示词或原始推理内容。
- **FR-010**: 系统 MUST NOT 在本地模型不可用时自动改用云端端点，也不得在云端失败时自动改用程序规则作答。

### Key Entities *(include if feature involves data)*

- **结构化输出模式**：一次模型调用要求的结构化约束形式，区分“首选严格模式”与“通用 JSON 模式”；影响模型返回是否直接受端点约束。
- **模型调用尝试**：一次逻辑调用下的一次或多次实际请求；记录所用结构化模式、是否回退、耗时与用量来源。
- **请求记录**：按请求标识汇总的轨迹；本功能要求其能区分端点能力不足与模型输出非法。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在配置云兼容端点且该端点不支持首选结构化模式的条件下，提交一个知识库内有依据的问题，能返回非空回答与至少一个来源，端到端耗时不超过既定的整次请求期限。
- **SC-002**: 同一条件下连续 3 次真实入口问题分析，均产出通过既有结构校验的结果，失败次数为 0。
- **SC-003**: 回退发生后，同一逻辑调用的实际请求次数不超过 2 次，且请求记录中可见“发生回退”。
- **SC-004**: 本地模型与显式测试模型路径的既有工程检查结论与修复前一致，无新增失败。
- **SC-005**: 端到端运行期间云端调用次数与记录的模型调用次数一致，且不出现未被记录的额外调用。

## Assumptions

- 用户自备的云兼容端点可稳定访问，且其通用 JSON 模式可用；端点密钥与额度由用户自行保证。
- 首选严格模式与通用 JSON 模式的取舍只在“端点拒绝首选模式”时触发；端点未拒绝时行为不变。
- 本功能只调整云端提供商的调用与失败归类，不改变解析、分块、索引格式、检索算法、预算数值与前端展示。
- 环境层面已存在一处第三方解压绑定不兼容，会在远端压缩返回时中断云端调用；本功能在客户端侧规避，不改动用户环境、不新增依赖。
- 本地模型在本机为纯 CPU 推理，完整循环可能超出既定整次请求期限；该性能限制不在本功能范围内，本功能不据此提高上限。
- 008 展示层重构与本功能互不影响；008 的验收结论仍以其自身报告为准。
