# 契约：云端兼容提供商的结构化输出与传输

**版本**：cloud-provider.v1 | **功能**：009-cloud-provider-compat | **状态**：设计已定，待实现与验证

本契约固定 `OpenAICompatibleProvider` 对外可观察的行为。本地 `OllamaProvider` 与 `FakeProvider` 不在本契约内，其行为必须保持不变。

## 1. 调用入口

```
complete(messages, *, tools=None, timeout_seconds=None, response_schema=None) -> ModelResult
```

- `messages`：已由调用方构造的对话消息，本契约不改变其语义。
- `tools` 与 `response_schema` 互斥；同时提供视为调用方错误。
- `response_schema` 存在时，返回内容的合法性由调用方（`complete_model`）用**同一个** schema 校验，本契约不降低校验强度。

## 2. 结构化模式协商

请求按以下顺序进行，最多 2 次实际请求：

| 序号 | 条件 | 模式 | 附带要求 |
|---|---|---|---|
| 1 | 带 `response_schema` | `json_schema`（严格） | 发送端点期望的严格结构约束 |
| 2 | 仅当第 1 次被端点以“该 response_format 类型不可用”类错误拒绝 | `json_object`（通用） | 必须同时把 schema 文本注入消息，使模型仍能得知字段与类型 |
| — | 不带 `response_schema` | `none` | 不发送任何结构约束 |

**约束**

- 回退是单向一次：不得出现 `json_object → json_schema`，也不得对同一逻辑调用发出第 3 次请求。
- 第 1 次成功时不得发生回退，调用次数不得增加。
- 端点拒绝以外的错误（超时、连接失败、鉴权失败）**不触发**回退，直接按失败处理。
- 回退后注入的消息内容由本系统生成（schema 文本 + 只输出 JSON 的要求），不得包含用户隐私之外的额外事实。

## 3. 传输契约

- 云端客户端必须显式不使用压缩编码，以保证远端返回内容可被正确处理。
- 该项设置不得影响本地提供商，不得引入新的运行时依赖。
- 密钥只从配置读取，不得写入日志、事件、异常文本或代码。

## 4. 返回值与可观测字段

`ModelResult` 在既有字段之外新增：

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `structured_mode` | `json_schema` \| `json_object` \| `none` | `none` | 本次调用最终生效的模式 |
| `structured_fallback` | boolean | `false` | 是否由严格模式回退而来 |

- 以上两个字段必须进入既有模型轨迹，并出现在执行事件的 `details` 中。
- 不得新增 SSE 顶层事件字段；不得在新增字段中携带提示词正文、推理内容或密钥。

## 5. 失败归类契约

| 触发条件 | 归类 | 用户可见文案原则 |
|---|---|---|
| 严格与通用模式均被端点拒绝 | 提供商不可用 | 说明模型服务不可用，不声称知识库无资料 |
| 模型返回内容无法通过 schema 校验 | 输出非法 | 说明模型未给出可用结构，不声称端点不可用 |
| 整次等待超时 | 超时 | 沿用既有超时文案 |
| 鉴权、额度、连接、传输失败 | 提供商不可用 | 不泄露密钥或响应正文细节 |

## 6. 不变量（必须继续成立）

1. 本地模型不可用时**不得**自动改用云端端点；云端失败时**不得**自动改用程序规则作答。
2. 请求级预算（简单 8 / 总 12）、工具上限 16、整次请求 300 秒、单次模型等待 120 秒均不变；回退不占用额外预算名额之外的调用。
3. 本地与测试提供商的行为、事件与失败原因与本次改动前一致。
4. 不修改知识库、索引、配置示例与前端契约。

## 7. 验证挂钩

| 契约条款 | 验证方式 |
|---|---|
| §2 模式协商与单次回退 | 单元测试：严格被拒 → 回退成功且恰好 2 次请求；严格成功 → 1 次请求且无回退；两次均被拒 → 失败且归类为提供商不可用 |
| §2 注入内容 | 单元测试：回退请求的消息中包含 schema 字段名，且不含密钥 |
| §3 传输契约 | 单元测试：客户端构造参数含不使用压缩编码，且未引入新依赖 |
| §4 可观测字段 | 单元测试 + 真实入口运行：轨迹与事件 `details` 出现 `structured_mode` 与 `structured_fallback` |
| §5 失败归类 | 单元测试：端点拒绝 ≠ 输出非法；非法内容 ≠ 端点不可用 |
| §6 不变量 | 既有后端测试全量回归；真实入口运行核对调用次数与期限 |
