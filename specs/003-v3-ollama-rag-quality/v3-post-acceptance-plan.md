## 1. 已验证的起点

本计划接续 [V3 总计划](plan.md)、[V3-5 验收](v3-5-report.md) 和 [V3-0 基线](v3-0-baseline.md)。这次是在**已登录的正式工作台及正式索引**中逐题提问，不是临时索引的模拟测试。

| 题目 | 正式库实测 | 关键证据 |
|---|---|---|
| Q1 上电前检查 | 通过 | 检查项、198–242 V、49–51 Hz；引用第 2、4 页 |
| Q2 过流保护阈值 | 通过 | 超过 16 A 持续 100 ms；引用第 4 页 |
| Q3 过流保护后恢复（补充题） | **部分通过** | 答出检查负载、清告警、重启，但漏掉“先断开负载、等待设备完全放电”；只引用第 4 页的简化问答表 |
| Q4 运行记录保留期 | 通过 | 三年、到期先进先出删除；引用第 4 页 |
| Q5 例行维护周期 | 通过 | 每六个月；引用第 3 页 |

四道历史基线题 **4/4**；五题中 **4 题完整、1 题部分通过**。五次问答各发生 1 次本地模型调用，工作台记录的实际 Token 合计 **9,377**，总耗时约 **225 秒**。目前正式库只有一份 `rag-test-knowledge-document.pdf` 测试文档，不能据此宣称真实业务文档已验收。

**已确认的失效链路**：Q3 的保留证据里已经包含第 3 页“OC-16”详细段落，其中有“先断开负载，等待设备完全放电”；最终回答却采用第 4 页简化问答表，省略前两步。`AnswerGenerator` 当前校验引文是否存在及答案数值是否受支持，不校验操作步骤是否齐全；`AnswerEvaluator` 对非空回答使用固定的忠实性 90、完整性 78，因此该题仍显示总体 84/100。现阶段不把遗漏归因于检索失败，也不假定仅修改提示词就能稳定修复。

## 2. 分阶段计划与交付物

### V3-6：固定失效样例与判定口径（先做）

1. 保存 Q3 的正式库检索排名、最终进入生成器的证据、答案与引文，区分“检索到”“送入模型”“最终引用”三个层次；对比第 3 页详细流程和第 4 页简表。
2. 将 Q3 期望步骤写成可核验的验收样例：断开负载 → 等待完全放电 → 检查负载端无短路 → 确认正常后清除告警 → 重新执行上电流程。语义等价表述可以接受，但不得省略安全前置步骤或改变顺序。
3. 增加一个能够暴露当前遗漏的回归用例，并记录当前评分误判；测试用例中的期望事实可针对样例，业务逻辑不得仅靠固定关键词匹配这份 PDF。

**交付物**：`v3-6-report.md`、Q3 回归用例、可重放的测试命令及失败证据。  
**通过条件**：能稳定复现“证据含完整步骤、回答遗漏、评分仍高”的问题，并明确下一阶段要修改的层次。完成后暂停。

### V3-7：修复操作流程回答的证据覆盖

1. 检查证据排序与截取：对“如何恢复／如何操作”类问题，保留完整的相关流程段落及前置条件；不能仅因简表相关度高就让它替代详细操作说明。优先采用章节结构、步骤关系和引文覆盖等通用机制，不把“断开负载”等词硬编码进通用代码。
2. 调整生成约束或答案校验，使回答中的操作序列与所引用的详细证据一致；如果无法确认关键步骤齐全，应明确提示信息不足或待核对，而不是给出看似完整的操作指导。
3. 保持现有引文逐字核验、数值校验及模型预算；不要为每次简单问答默认增加一个云端或本地 Judge 调用。

**交付物**：证据选择／生成相关代码与针对性测试、`v3-7-report.md`。  
**通过条件**：Q3 答案完整覆盖上述步骤并引用第 3 页详细流程；Q1、Q2、Q4、Q5 不回退；简单题不超过现有每请求 2 次模型调用预算，云端调用为 0。完成后暂停。

### V3-8：让评估结果可信，并在正式库回归

1. 区分“引文有效”“事实受支持”“步骤完整”三种判断。无法自动验证的完整性不要继续显示固定高分或暗示已核验；需要时显示“未验证”，并保留可解释原因。
2. 将 Q1–Q5、无证据、数值冲突、操作步骤缺失纳入回归；至少重复运行 Q3 三次，检查本地小模型波动。核对引用页、答案、调用次数、实测／估算 Token 与耗时。
3. 先在隔离环境验证，再通过工作台验证正式索引；不以临时库结果替代正式库结果。记录质量改善与 Token、延迟变化，不为追求评分而无界增加调用。

**交付物**：评估与前端展示的必要调整、自动化测试、正式库验收记录 `v3-8-report.md`。  
**通过条件**：五题完整正确且来源可核对，Q3 连续 3 次不遗漏安全前置步骤；故意缺步骤的答案不能获得“完整”判定；每次调用与 Token 可审计。完成后暂停。

### 后续独立事项：真实业务 PDF 试点

目前只有测试 PDF。待用户提供拟使用的业务文档并明确同意导入后，先做文档清单、权限与敏感信息检查、解析预览和现有索引备份，再选择少量代表性 PDF 建立独立验收题集。导入、替换或重建正式库均需另行确认；**不属于 V3-6 至 V3-8 的自动操作**。

## 3. 边界与风险

- 本计划只涉及文本 PDF 问答质量；不扩展 OCR、多模态、部署或多用户权限。
- 操作类答案可能影响设备安全。系统的来源引用不能替代原始设备手册或人工复核；若关键前置步骤缺失，应优先暴露不确定性。
- 不删除、覆盖或自动重建正式知识库；不改模型配置、密码或密钥。
- 本文是 V3 已完成后的补充计划，不追溯改写既有 V3-0 至 V3-5 验收结论。项目当前无 Git 元数据，且 Spec Kit 前置脚本会误指向 V2；本次只生成此计划文件，不执行完整 Spec Kit 设计产物生成流程。
