## 2. 核验边界与展示

[核验器](../../backend/app/rag/evaluator.py)只检查能实际证明的引用定位，修正前单独提供有效编号也会显示 `verified`；新增测试先复现失败，随后修正。

| 实际检查 | 当前状态与含义 |
|---|---|
| 检索到上下文 | 已取得证据，不代表答案正确 |
| 只有有效编号 | 未评估引文内容；原因明确说明仅有编号 |
| 逐字引文与文档/页码/章节匹配 | 引文已核验，仅表示能定位原文 |
| 未知编号、错误引文或页码 | 引文存在问题 |
| 答案数值、事实的语义正确性 | 未评估，不能由引用存在推导 |
| 操作步骤是否齐全 | 未评估，不提供完整性分数 |

前端已有四项独立状态及“来源可定位不等于事实正确或答案完整”的说明，本阶段无需再改变业务界面。补充核验卡测试，确认有效引用不能让数值或步骤状态自动变成已核验。

新增 [核验边界测试](../../backend/tests/unit/test_v3_8_verification.py)明确验证：有效的末尾步骤引用可以定位，但遗漏安全前置步骤的答案仍不会得到“完整”判定；无证据不调用答案模型；数值冲突展示双方来源，不给唯一正确性高分。

这些边界测试没有把固定题目的动作词加入生产评分器，也没有增加模型调用。

## 4. BM25 资源问题与失败记录

本次首先发现生产默认 BM25 缓存缺少资源。使用现有 FastEmbed 下载流程补齐 [Qdrant 官方资源](https://huggingface.co/Qdrant/bm25)，缓存版本 `22b8d2af71a76161e18dd432d2cee0eefa66e412`，18 个文件，共 25242 字节；不是新下载数 GB 大模型。

默认在线构造可以加载，但已安装 FastEmbed 的离线加载检查仍要求上游没有的 `mock.file`、`tamil.txt`。首次隔离尝试因此失败，不能将它算作 Q3 稳定性样本。

诊断脚本现在在问答前定位真实缓存，核对 `english.txt` 长度及 Git blob 指纹，显式指定该缓存目录；保持当前默认 stemming 和真实的 179 个英文停用词，不改为上一阶段空词表的模拟离线目录。逐题核对查询向量一致性。

生产 `.env` 和编码器源码没有修改；正式后台仍沿用默认构造，首次加载可能访问 Hugging Face 资源元数据。因此“没有云端模型调用”不等于“应用所有初始化都不联网”，本次不宣称整个应用完全断网启动。

首次失败发生在完整捕获保存前，模型用量没有保存，可能已经执行分析调用，**不能回填成零调用或给出精确总 Token**；当时工具仍有最多两次本地调用的硬上限。上述 16414 Token 仅为七次有效捕获的可审计合计，不包含该失败尝试。[资源设置记录](v3-8-setup-observation.json)单独保存此限制。
