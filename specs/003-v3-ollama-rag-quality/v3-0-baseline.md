## 2. 解析与索引现状

- `PdfParser` 使用 PyMuPDF `page.get_text("text")`。源 PDF 4 页均有文本：各页字符数分别为 **289、804、788、626**，合计 **2507**（按逐页 `strip()` 后文本计算）。上述五题的关键词在提取文本中存在，中文没有乱码。入库的 `extracted.md` 是纯文本加 `.md` 后缀，不是保留标题/表格结构的 Markdown。
- 原文有 **6 个**编号章节（第 2–4 页），而当前 `_is_heading` 对这 6 个标题识别数为 **0**；却把 `198 V 至 242 V`、`300 ms`、`16 A`、`3 年` 等 **12 行**数值/表格内容误识别成章节标题。由此生成 **13 Parent、14 Child**，多个 Parent 只有 **21–33 字**，有的标题跨错章节。页码也是切分时聚合的范围，不代表结构正确。
- 当前文档库只有上述 1 份 ready 文档；Qdrant 实际集合却有 **50 个 Child Point**：当前文档 14 个，另外两个已不在文档库的文档共 **36 个**。`Retriever` 会在 Qdrant 取 Top-7 *之后*过滤失效文档，所以旧数据虽然不直接进入最终答案，却会占据候选名额。索引与文档库不一致。
- `.env` 当前配置 `USE_TRANSFORMER_EMBEDDING=false`：Dense 为确定性哈希向量，不是语义模型；Sparse 为本地 BM25，查询融合使用 DBSF，`RETRIEVAL_TOP_K=7`、`RETRIEVAL_MIN_SCORE=0.4`。以下复现使用生产 Qdrant 的一致性 SQLite 快照，并在禁网模式下使用项目自带的 BM25 离线适配；四题的最高分与历史日志逐一一致。没有查询在线服务，避免触发云模型计费。

## 6. 五类问题归因与下一阶段入口

1. **解析失败？** 不是“空 PDF / 中文乱码”：2507 字及关键事实均可提取；但标题、表格行和阅读结构丢失，是明确的结构解析失败。
2. **召回失败？** 不是单纯没召回：Q2/Q3/Q4 的关键事实在 Top-5 内。但旧文档占用候选名额、Dense 使用哈希向量、Q1 完整清单不稳定，检索质量确有问题。
3. **上下文拼错？** 是四道历史题里三题失败的直接原因。`orchestrator` 在命中的 Child 中找**第一个长度 <240** 的片段，读取其 Parent；`collect_answer` 一旦有 `parent_contexts`，就**只采用该 Parent，丢弃其余 Child/Parent 证据**。恰好错误切分产生了 21–33 字 Parent。Q1/Q2/Q4 都落在无关数值块，形成与“4 题仅 1 题正确”一致的复现。
4. **回答生成失败？** 历史答案正文未留存，不能独立归责于 LLM。对 Q1/Q2/Q4，模型输入已缺事实；即使换 Ollama，也不会自动修好这一层。Q5 上下文含答案，实际回答仍需新的可审计测试确认。
5. **评估误判？** 当前 `AnswerEvaluator` 对任何非空且非固定 fallback 的回答给 `faithfulness=90`、`completeness=78`，相关性通常 72/85；并未核对数值、来源与真实答案。即便上下文指向 `30 秒` 而问题询问 `三年`，也可能得较高分。历史具体分数未留存，误判风险由代码可证。

V3-0 结论：主要阻断在**切分结构 → 选错短 Parent → 最终上下文丢失事实**，另有旧索引污染和评价虚高。原计划要求记录的“历史实际答案/真实输出 Token”因现有日志缺失而无法补全，已明确标注，不能伪造。下一阶段应先修复结构与证据选择、清理索引一致性，再对比模型答案；本次按用户要求停在 V3-0。
