# Feature Specification: 按工具需求分流聊天

**Feature Branch** `codex/model-driven-agent-loop`

**Created** 2026-11-13

**Status** 阶段 A 工程实现完成，见[阶段报告](phase-a-report.md)。等待用户验收。

**Input** 模型先判断消息是否需要工具。可直接回答时由模型回复，需要知识库时再判断信息是否足够。

## User Scenarios & Testing

### User Story 1 - 普通聊天直接得到回复（P1）

问候、致谢、通用解释和根据用户已提供的文字进行改写时，工作台直接显示模型回复。例子“你好”应显示中文问候或邀请继续提问，保持普通答案状态。

独立验收以普通聊天首答及其后续消息验证。检索调用、检索问题分析、待补充状态和文档来源均为空。知识库索引不可用时该路径仍可完成。

### User Story 2 - 需要知识库时判断能否检索（P1）

明确要求查文档或需要项目、设备、制度等专属资料时，先确认所指对象和必要条件。信息足够时沿现有知识库研究流程作答并显示实际来源。缺少决定检索目标的信息时只询问关键缺口，收到补充后再分析和检索。

独立验收覆盖一个明确的文档问题、一条缺少文档或设备指代的问题和后续补充。分流调用在查询改写前发生，澄清轮没有检索。

### Edge Cases

- 同一条消息同时问候并提出文档问题时，仍进入知识库路径。
- “你是谁”“你是什么模型”等自我介绍问题直接回答，先说明「文脉」知识助手的产品身份。用户明确追问底层模型或提供方时，仅依据已确认的系统信息回答。
- 回顾已有会话内容可以直接回答，要求重新核对文档时使用知识库。
- 待补充状态下，默认消息用于补充原问题。显式开始新问题时重新判断工具需求，取消保持零模型调用。
- 分流输出无效或提供方失败时，沿用当前请求错误状态。

## Requirements

### Functional Requirements

- **FR-001** 每条新消息首先由模型判断是否需要知识库工具，依据当前消息与已有会话上下文。
- **FR-002** 无工具路径使用未绑定检索工具的模型生成回复，以普通流式答案完成并写入会话历史。
- **FR-003** 知识库路径在执行工具前进行查询改写和充分性判断，只有缺少影响检索的必要信息时才进入现有待补充状态。
- **FR-004** 公共事件和用量反映实际路径，直接回答使用空来源，澄清保留继续、新问题及取消操作。

### Key Entities

- 工具需求是本轮模型产生的二选一决定。检索充分性仍由既有问题分析描述。

## Success Criteria

### Measurable Outcomes

- **SC-001** “你好”收到中文普通答案，完成状态为 `completed`，检索、问题分析、澄清事件和来源均为零。
- **SC-002** 明确文档问题经过分流、改写及检索，并带有实际命中的来源。
- **SC-003** 缺失关键指代的文档问题先产生澄清，补充后成功检索并清除待办。
- **SC-004** 分流失败不会触发检索，下一条新消息可在同一会话重新进入分流。

## Assumptions

- 本阶段的工具范围为现有知识库检索。通用聊天默认以当前消息的语言回复，未要求重新查证时可使用已知对话内容。
- 既有研究子图、正式题库和数据操作边界继续适用。
