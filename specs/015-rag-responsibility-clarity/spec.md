# Feature Specification: 清楚的 Agent 核心与基础能力归属

**Created**: 2026-10-22
**Status**: A 工程完成，待用户验收；B 未执行
**Input**: 用户指出千行文件比参考 GitHub 臃肿，要求像参考项目一样清楚。八文件布局表达 Agent 核心的清晰职责，不再要求整个 RAG 系统全部实现都放进八文件。

## User Scenarios & Testing

### User Story 1 - 维护者从核心目录理解一次问答 (Priority: P1)

维护者能直接找到图、节点、路由、状态、提示、结构和工具，阅读模型动作及证据流时不必穿过提供商协议、索引持久化和旧独立接口。

**Why this priority**: 014 仅改变文件归属，导致工具和节点承担大量无关职责；这是本次需纠正的主要问题。
**Independent Test**: 核对核心职责和依赖，并以相同受控问答验证行为不变。

**Acceptance Scenarios**:

1. **Given** 维护者查看 Agent 核心，**When** 找到一次问题分析、动作选择、工具执行和答案交付，**Then** 各自有清楚入口，核心目录不承担提供商或索引实现。
2. **Given** 维护者修改编码、索引或模型协议，**When** 定位实现，**Then** 能在明确的基础能力模块完成修改，不修改图或节点业务。
3. **Given** 现有问答和独立调用，**When** 调整归属，**Then** 参数、结果、原文、用量、超时与失败行为保持，不为缩短文件删除功能。

### User Story 2 - 重复执行流程有可验证的简化依据 (Priority: P2)

维护者能够分辨职责迁移与真正减少重复实现；简化候选必须展示调用证据、影响及验证，不能把移动行数当作代码削减。

**Independent Test**: 对候选逐项给出正常调用、独立用途和前后行为检查，未验证的 SDK 替换不进入实施。

### Edge Cases

- 原独立旧能力仍有脚本/测试调用，当前没有授权删除。
- 参考项目的模型/嵌入配置与本地不同，不能为模仿目录替换现有提供商或 ONNX 后端。
- 跨模块的答案解析、查询规范化、会话摘要可能产生反向依赖，必须按符号处理。
- 动态类属性、缓存、租约、迟到调用与异常路径不能只靠普通文本搜索判断。

## Requirements

### Functional Requirements

- **FR-001**: Agent 核心只负责图、节点、边、图状态、提示、Agent 输入/输出结构及工具接口；基础设施实现有独立且明确的归属。
- **FR-002**: 模型适配、共同调用治理、知识索引/检索、会话存取和请求交付按真实职责组织，不创建含混的大型公共工具文件。
- **FR-003**: 正常问答与独立旧能力可以区分，原有独立能力保留，不能以不在主流程为由删除。
- **FR-004**: 保持现有能力与行为，包括两个模型协议、原文/来源、P1/P2、额度/lease/期限、迟到隔离、历史、SSE 和诊断。
- **FR-005**: 不更换模型、嵌入、提示语义、依赖或前端；不操作正式数据或调用真实模型。
- **FR-006**: 实施前给出完整符号归属及循环风险；实施时迁移应用、脚本、测试和源码指纹清单。
- **FR-007**: 验证覆盖静态结构、算法和隔离回归，保留历史失败和未测范围，不以通过数证明架构简洁。
- **FR-008**: 真正削减候选须给出行为等价证据；尚未确认的 SDK 复用及接口移除不自动执行。
- **FR-009**: 按阶段交付并保存报告，不自动推进下一阶段或真实评测。

### Key Entities

- **核心职责**：一次问答中的图、节点、状态、模型动作与工具边界。
- **基础能力**：模型调用、数据访问、会话与请求交付的既有实现。
- **兼容能力**：已存在但不驱动当前主流程的独立调用接口。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 核心节点中提供商适配和索引持久化实现为零，核心工具中模型适配/预算账本/向量存储实现为零。
- **SC-002**: 全部 161 个现有顶层能力均有明确归属，未知用途被删除的数量为零。
- **SC-003**: 结构调整后的隔离回归没有新增产品失败，提示、协议和数据约束保持。
- **SC-004**: 每个真正削减候选都有使用证据及验证要求；纯职责迁移不宣称总实现减少。
- **SC-005**: 阶段报告与原始命令完整，真实模型和正式数据操作为零。

## Assumptions

- 保留一个 Agent 包 rag；core/knowledge 的基础实现不是第二套 Agent。
- 设计后用户明确指示“继续”，本轮仅实施 A；B 须在 A 验收后另行指示。
- 单文件行数是审阅信号，不能作为删功能或压缩排版的理由。
